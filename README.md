# Сайт храма Преподобного Серафима Саровского (село Палкино)

Проект для локальной разработки: Next.js-сайт и Express API с админ-панелью лежат в одном репозитории и запускаются одной командой.

```
sitepalkino/
├── app/                  # сайт на Next.js
│   ├── lib/api.ts        # клиент публичного API
│   ├── components/       # карточки новостей и расписания
│   ├── news/             # страница новостей
│   └── schedule/         # список и календарь богослужений
├── server/               # API + админка
│   ├── src/              # Express-сервер
│   │   └── data/         # демонстрационные данные для локального запуска
│   ├── admin-panel/      # React-админка (собирается в dist/)
│   ├── uploads/          # загруженные картинки
│   └── .env              # локальные настройки API (не коммитится)
├── scripts/dev.mjs       # одновременный запуск сайта и API
├── .env.local            # адреса API для сайта (не коммитится)
└── package.json
```

## Быстрый старт

Нужен Node.js 20+ и npm.

```bash
# 1. Зависимости сайта
npm install

# 2. Зависимости API (если папки server/node_modules ещё нет)
npm run setup:server

# 3. Настройки API (если server/.env ещё нет)
cp server/.env.example server/.env
#    Откройте server/.env и задайте:
#    ADMIN_PASSWORD=<пароль для входа в админку>
#    SESSION_SECRET=<любая длинная строка>
#    DB_ENABLED=false  (пока без MySQL)

# 4. Адрес API для сайта
cp .env.example .env.local

# 5. Запуск сайта и API вместе
npm run dev
```

После запуска:

| Что | Адрес |
|---|---|
| Сайт | http://localhost:3000 |
| API | http://localhost:3001/api/health |
| Админка | http://localhost:3001/admin |

Остановить всё — `Ctrl+C` в терминале, где запущен `npm run dev`.

Если админка открывается с ошибкой 503, её нужно собрать:

```bash
npm run setup:admin
```

## Инструкция для программиста

### Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Запускает API на 3001 и сайт на 3000 одновременно |
| `npm run dev:web` | Только сайт (`next dev`) |
| `npm run dev:server` | Только API (`node --watch`) |
| `npm run dev:admin` | Админка в режиме разработки Vite на 5173 |
| `npm run build` | Статическая сборка сайта в `out/` |
| `npm run build:admin` | Пересборка админки |
| `npm run setup:server` | `npm install` для API |
| `npm run setup:admin` | Установка зависимостей и сборка админки |
| `npm --prefix server test` | Тесты API (16 тестов, память) |

Проверка типов сайта:

```bash
npx tsc --noEmit
```

### Быстрая проверка, что всё связано

1. Откройте `http://localhost:3001/api/news` — должен вернуться JSON с новостями.
2. Откройте `http://localhost:3000/news` — те же новости должны быть на странице.
3. В админке создайте новость, сохраните и обновите `http://localhost:3000/news` — новость должна появиться без пересборки.
4. В админке измените расписание и обновите `http://localhost:3000/schedule`.

Если шаг 1 работает, а шаг 2 — нет, смотрите `API_URL` в `.env.local` и ошибки в терминале `npm run dev`.

### Как устроена связка
1. `npm run dev` запускает `server/src/server.js` и `next dev`.
2. Серверные компоненты Next вызывают API по адресу из `API_URL` (по умолчанию `http://127.0.0.1:3001`).
3. Браузер получает картинки из `/uploads` по адресу из `NEXT_PUBLIC_API_URL`.
4. Админка сохраняет новости и расписание в API.
5. В dev-режиме сайт не кеширует ответы API: после сохранения в админке достаточно обновить страницу сайта.

Переменные окружения сайта (`.env.local`):

```bash
NEXT_PUBLIC_API_URL=http://localhost:3001  # для браузера и картинок
API_URL=http://127.0.0.1:3001              # для серверного рендера Next
```

Переменные API (`server/.env`):

| Переменная | Назначение |
|---|---|
| `PORT` | Порт API, по умолчанию 3001 |
| `ADMIN_PASSWORD` | Пароль входа в админку |
| `SESSION_SECRET` | Секрет сессий, для локальной разработки можно любой |
| `CORS_ORIGIN` | Адреса, которым разрешены админские запросы с cookie |
| `DB_ENABLED` | `false` — данные в памяти, `true` — MySQL |
| `APP_TIMEZONE` | Часовой пояс расписания, `Europe/Moscow` |
| `MAX_UPLOAD_MB` | Максимальный размер одной картинки |

По умолчанию `DB_ENABLED=false`: данные хранятся в памяти и **пропадают при перезапуске API**. Для сохранения между перезапусками включите MySQL:

```bash
# один раз: создать базу и таблицы
DB_ENABLED=true npm --prefix server run db:init

# затем в server/.env:
DB_ENABLED=true
DB_HOST=localhost
DB_USER=root
DB_PASSWORD=
DB_NAME=palkino_site
```

Подробнее про MySQL, загрузку файлов и выкладку — в `server/README.md`.

### Где менять данные

- **Новости и расписание** — через админку (они попадают в API и на сайт).
- **Демонстрационные данные для локального запуска** — `server/src/data/news.js`, `server/src/data/schedule.js`, `server/src/data/temple.js`. После изменения API перезапускается автоматически.
- **Статические тексты** («О храме», «История», «Таинства», реквизиты) пока лежат в компонентах сайта. Их перенос в API — следующий этап.

### API

Публичные методы:

| Метод | Адрес | Описание |
|---|---|---|
| GET | `/api/health` | Состояние API и хранилища |
| GET | `/api/info` | Данные о храме |
| GET | `/api/news?limit=` | Новости, свежие первыми |
| GET | `/api/news/:id` | Одна новость |
| GET | `/api/schedule?upcoming=false&limit=100` | Расписание |
| GET | `/api/schedule/upcoming` | Ближайшие богослужения |

Админские методы требуют cookie-сессию и доступны по `/api/admin/*`. Вход — `POST /api/admin/login` с `{ "password": "..." }`.

### Ограничения текущего этапа

- Сайт собран как статический экспорт (`output: 'export'`). При `npm run build` данные забираются из API один раз и «замораживаются» в `out/`. Для локальной разработки это не важно, но на сервере понадобится либо пересборка после изменений, либо переход на SSR.
- При статической сборке API должен быть запущен, иначе новости и расписание попадут в `out/` пустыми.
- В `server/src/data/schedule.js` есть демонстрационная запись на 8 ноября 2026 года. Замените её реальным расписанием.
- Сессии админки хранятся в памяти: после перезапуска API нужно войти заново.

## Инструкция для пользователя (редактора сайта)

1. Запустите проект командой `npm run dev` (это делает программист или администратор компьютера).
2. Откройте админку: **http://localhost:3001/admin**.
3. Введите пароль, который указан в `server/.env` в строке `ADMIN_PASSWORD`.
4. Выберите вкладку:
   - **Новости** — «+ Добавить новость», заполните заголовок, дату, краткое описание и текст, при необходимости загрузите фотографии. Сохраните.
   - **Расписание** — выберите день, добавьте время и название богослужения. Сохраните.
5. Откройте сайт **http://localhost:3000** и обновите страницу — изменения уже должны быть видны.
6. Чтобы изменения не пропали после перезапуска, нужна включённая MySQL (см. раздел для программиста). Без неё данные живут только до перезапуска.

Важно:

- В демонстрационном расписании есть запись «Демонстрационная запись для локальной разработки» — её нужно заменить настоящей.
- Пароль из локального `server/.env` нельзя использовать на настоящем сервере.
- Для публикации сайта в интернете пока недостаточно просто запустить `npm run dev`: нужен сервер, домен и отдельная настройка выкладки.

## Частые проблемы

**Порт 3000 или 3001 занят.** Остановите старый процесс (`Ctrl+C`) или запустите сайт/API на других портах. При смене порта API обновите `.env.local` и `CORS_ORIGIN` в `server/.env`.

**Сайт открывается, но новостей и расписания нет.** Проверьте `http://localhost:3001/api/health`. Если API не отвечает, запустите `npm run dev` заново или отдельно `npm run dev:server`.

**Админка возвращает 503.** Не собрана админка: выполните `npm run setup:admin`.

**После перезапуска пропали новости.** Используется хранилище в памяти. Включите MySQL или не перезапускайте API во время демонстрации.

**Картинки не видны.** Проверьте, что в `.env.local` указан `NEXT_PUBLIC_API_URL=http://localhost:3001`, а API запущен.

**После `npm run build` dev-сервер падает или зависает с ошибкой Client Manifest.** Это конфликт кеша production-сборки и dev-режима. Остановите процессы, удалите `.next` и запустите заново:

```bash
rm -rf .next
npm run dev
```

**Первый запуск страницы долгий.** Next собирает страницу и тяжёлые компоненты календаря при первом обращении. Последующие открытия должны быть быстрыми; если страница висит минутами — смотрите пункт выше про `.next`.
